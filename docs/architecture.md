# البنية التقنية

## المكوّنات

| الخدمة | التقنية | الدور |
| --- | --- | --- |
| `services/vision` | Python، YOLO11 (pose + detect)، ByteTrack، OpenCV، ONNX Runtime | يستقبل بث كل كاميرا، ويكشف الأشخاص والأغراض ويتتبعهم، ويطبق القواعد، ويحفظ المقاطع مع تمويه الوجوه، ويرسل الأحداث والقراءات للخادم |
| `services/api` | NestJS (TypeScript)، PostgreSQL | المصادقة والصلاحيات، واستقبال الأحداث، والمراجعة، والبث المباشر (SSE)، والتقارير، وسجل التدقيق، والحذف التلقائي، وخدمة الواجهة |
| `services/analytics` | pandas، scikit-learn، statsmodels | كل 15 دقيقة: الخط الأساسي لكل منطقة، والانحراف، والشذوذ، ومؤشر التوتر، والتنبؤ، وتقرير ما يسبق الحوادث |
| `services/web` | React، Vite، Recharts | مركز القيادة بالعربية (RTL)، والخط مضمّن ولا يحتاج إنترنت |
| `training/` | PyTorch، ONNX | تجهيز بيانات العراك، والتدريب، والتقييم، والتصدير، وقياس السرعة، وتقييم الخط كاملاً على مقاطع مصنّفة |

## مسار الفيديو داخل خدمة الرؤية

1. **`stream.py`**: قارئ في خيط مستقل لكل كاميرا، يعيد الاتصال تلقائياً ويحتفظ بأحدث إطار فقط، فلا يتراكم تأخير إذا كان الكشف أبطأ من البث.
2. **`detector.py`**: نموذج pose يعطي صندوق كل شخص و17 نقطة للجسم، مع تتبع ByteTrack. نموذج الأغراض (حقائب) يعمل كل 5 إطارات.
3. **`engine.py`**: يحدّث مسار كل شخص، ويحدد المناطق التي يقف فيها (بموضع القدمين)، ويمرر الإطار على القواعد، ويجمع القراءات كل دقيقة.
4. **`rules/`**: قاعدة لكل نوع حادثة، ولكل قاعدة فترة تهدئة تمنع تكرار التنبيه نفسه.
5. **`tamper.py`**: يقارن الصورة بمرجع يتحدث ببطء، ليكشف تغطية العدسة أو تشويشها أو تحريك الكاميرا.
6. **`clips.py`**: يحتفظ بآخر 10 ثوانٍ، ويكتب مقطعاً من 10 ثوانٍ قبل الحدث إلى 10 بعده، بترميز H.264 مع وجوه مموّهة.
7. **`client.py`**: يرسل للخادم، ويخزّن الرسائل مؤقتاً إذا انقطع الاتصال.

## قاعدة البيانات

المخطط في `services/api/db/migrations/001_init.sql`، ويطبّقه الخادم تلقائياً عند التشغيل.

- `areas` و`cameras` و`zones`: المنشأة ومناطقها والكاميرات ومناطق الرصد في كل كاميرا.
- `events`: التنبيهات وقرار المراجعة وسببه، وحقل `shadow` لتنبيهات وضع الظل.
- `zone_metrics`: قراءة كل دقيقة لكل كاميرا ومنطقة: الكثافة، والحركة، وأكبر تجمّع، والركض. تجميعية فقط وبدون أي هوية.
- `camera_status` و`camera_heartbeats`: حالة الكاميرات وتاريخ نبضها لحساب استمرار التشغيل.
- `area_scores` و`area_forecasts` و`analytics_reports`: مخرجات التحليل.
- `headcounts`: نتائج العدّ.
- `audit_log`: سجل التدقيق، ويمنع تعديله أو حذفه trigger على مستوى قاعدة البيانات.
- `settings`: وضع الظل، ومدد الاحتفاظ، والمنطقة الزمنية، ومسار نموذج العراك.

## الواجهة البرمجية (مختصر)

| المسار | الصلاحية | الوظيفة |
| --- | --- | --- |
| `POST /api/auth/login` | عام | الدخول (5 محاولات فاشلة لكل 10 دقائق) |
| `GET /api/ingest/config` و`POST /api/ingest/{events,metrics,heartbeat}` | مفتاح الخدمة | لخدمة الرؤية فقط |
| `GET /api/events` و`/events/stream` و`POST /events/:id/review` | مشغّل | التنبيهات والبث المباشر والقرار |
| `POST /api/events/:id/media-token` | مشغّل (التصدير: مشرف) | رابط مؤقت لمدة 5 دقائق للمقطع، ويُسجَّل في التدقيق |
| `GET /api/analytics/{areas,hotspots}` | مشغّل | المؤشر والمناطق الساخنة |
| `GET /api/analytics/precursors` و`/reports/*` | مشرف | التقارير ومؤشرات النجاح |
| `GET /api/audit` | مدير | سجل التدقيق |
| `/api/users` و`/cameras` و`/zones` و`/areas` و`PATCH /settings` | مسؤول النظام | الإدارة |
