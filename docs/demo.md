# العرض الحي على المسؤولين (25 دقيقة)

## التجهيز قبل العرض بيوم

```bash
# 1. المقاطع: صوّر مقاطع تمثيلية قصيرة (عراك مُمثَّل، سقوط، دخول منطقة، تجمّع) وضعها في samples/
#    أو للتجربة السريعة:
deploy/demo/make_sample.sh
# 2. شغّل النظام مع كاميرات محاكاة (خادم RTSP يبث المقاطع بشكل متكرر):
docker compose -f deploy/docker-compose.yml --profile demo up -d --build
# 3. بيانات تاريخ تجريبية لـ4 أسابيع، حتى تظهر الخريطة والتنبؤ والتقارير:
docker compose -f deploy/docker-compose.yml exec api node dist/scripts/seed-demo.js --rtsp-base rtsp://mediamtx:8554
docker compose -f deploy/docker-compose.yml exec analytics python -m rased_analytics.runner --once
```

البيانات التجريبية تُظهر لافتة «بيانات تجريبية» في كل الصفحات. لا تُخفها، وقلها في العرض بوضوح.

مستخدمو العرض بكلمة المرور `Demo-Password-2026`: `demo.operator` و`demo.supervisor` و`demo.manager`.

سجّل العرض كاملاً فيديو احتياطياً، في حال تعطل أي شيء.

## السيناريو

| الدقيقة | المحتوى | الصفحة |
| --- | --- | --- |
| 0 إلى 3 | المشكلة: 16 بثاً على شاشة واحدة، وسؤال للحضور: أين الحادثة؟ | (شاشة الكاميرات المعتادة) |
| 3 إلى 10 | كشف لحظي: شغّل مقطع العراك، ثم السقوط، ثم دخول المنطقة. التنبيه يظهر مع الصوت خلال ثوانٍ، وافتح المقطع (الوجوه مموّهة)، وأكّد التنبيه أمامهم | التنبيهات |

| 15 إلى 18 | الأرقام: مؤشرات النجاح مقابل المستهدف، ومن أين يأتي كل رقم | التقارير |
| 18 إلى 21 | الضمانات: القرار بيد المشغّل، ولا تعرّف على الوجوه، والتشغيل محلي، وسجل التدقيق يُظهر مشاهدتك للمقطع قبل دقائق | سجل التدقيق |
| 21 إلى 25 | القرار المطلوب: الموافقات الست في خطة المشروع، ثم الأسئلة | (المستند) |

## أسئلة متوقعة

- **ماذا لو أخطأ النظام؟** لا يتخذ أي إجراء بنفسه، ويُرفض التنبيه بسبب، والأسباب تُستخدم لضبط النظام. والتشغيل يبدأ أسبوعين بوضع الظل.
- **هل يتعرف على النزلاء؟** لا. لا يوجد تعرّف على الوجوه، والتنبؤ للأماكن والأوقات فقط.
- **هل يحتاج إنترنت أو سحابة؟** لا. خادم واحد داخل المنشأة.
- **هل نغير الكاميرات؟** لا. يعمل على كاميرات IP الحالية عبر RTSP.
- **كم كاميرا لكل خادم؟** يُقاس على الخادم الفعلي بـ`benchmark.py`، والمستهدف 8 كاميرات أو أكثر لكل كرت.
